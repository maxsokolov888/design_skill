# Инспектор tasteskill — перевод проверок в наши правила

**Где читать:** шаг «проверка», перед тем как открыть `report.json`.
**Что это:** сторонний пакет (MIT) со своим домом правил; прогоняет страницу в headless Chrome на 1440, 768 и 390 и пишет `report.json` — уровень FAIL/WARN, id проверки, замер, подсказка по починке. Инспектор проверяет 88 признаков. Часть из них — наш норматив, часть — вкус авторов пакета, и часть прямо противоречит исследованию, на котором пакет построен.

**Главное правило чтения:** провал инструмента переводится в находку только через таблицу ниже. У каждой строки стоит номер нашего правила; где номера нет — инструмент не используется. Строка без номера в отчёт не попадает, иначе начнёшь ругать сильные сайты за то, что норматив разрешает.

## Команда запуска

Только через HTTP: путь `file://` инспектор принимает за локальный файл и падает. Нужен Node 22+ и установленный Chrome. Инспектор — отдельный пакет (ставится из его репозитория), в этот не входит.

```bash
# 1. из папки со сборкой поднять HTTP-сервер
cd out && python3 -m http.server 8765 &

# 2. прогнать инспектор по адресу, а не по пути к файлу
node inspect.mjs http://127.0.0.1:8765/index.html \
  --out /tmp/inspect --json

# 3. погасить сервер
kill %1
```

Результат — `/tmp/inspect/report.json` и скриншоты desktop/tablet/mobile. Занимает около 40 секунд.

## Что игнорируем как вкус авторов пакета

Провал не переносится в отчёт. Причина у всех одна: в лекциях такого запрета нет, а исследование показывает обратное — эти приёмы чаще встречаются у сильных сайтов.

| id проверки | Почему игнорируем |
|---|---|
| `mono` | Моноширинные ярлыки — 44% у сильных против 24% у слабых. Это мода галереи, а не признак слабости |
| `numbering` | Нумерация 01/02/03 — 38% у сильных против 21% у слабых |
| `eyebrow` | Надзаголовок разрешён: один на страницу и только если несёт факт («для селлеров Wildberries и Ozon»), а не украшение. Провал инструмента сам по себе ничего не значит |
| `hairline` | Тонкие линии — 61% у сильных против 52% у слабых; не различает |
| `dashed` | Пунктир — эстетика авторов пакета, в норматив не входит |
| `glass` | Размытие подложки — 32% у сильных против 39% у слабых; не различает |
| `pill-nav` | Пилюля-навигация — вкус пакета. У нас капсула разрешена набором 8.8, вопрос только в осознанности выбора и единстве системы |
| `palette-cream`, `palette-purple`, `palette-terracotta`, `palette-claude` | Эвристика авторов пакета по конкретным палитрам. В лекциях такого запрета нет; цвет оценивается по 1.1–1.17 и 10.22–10.27 |

## Что не наш норматив

| id проверки | Почему не наш |
|---|---|
| `few-pictures`, `no-real-pictures` | Требование «не меньше четырёх изображений» — из исследования галерей (10.28) и у нас работает как ориентир, а не как провал. Лекция задаёт другое: изображение читается первым (4.6) и должно нести работу |
| `no-footage`, `no-poster` | Видео и постеры лекции не задают вовсе |
| `still-page`, `scene-*`, `many-scenes`, `long-pin`, `side-scroll`, `pinned-over-picture` | Бюджеты движения и сценарные приёмы — практика галерей. Наше движение описано в 10.40–10.43, и «не меньше восьми движущихся элементов» там ориентир, а не приговор спокойному корпоративному сайту |

Итог: строки без номера правила в отчёт не идут. Порядок работы с выводом — взять только строки с номером, подтвердить каждую скриншотом, ложное отбросить с причиной.

## Оговорка про Linear

Инспектор ругает и сильные сайты: на главной Linear — одного из сильнейших продуктовых сайтов отрасли — он выдал 14 провалов и 11 предупреждений. Среди них заголовки длиннее двух строк, моноширинные ярлыки, тонкие линии — то, что наш норматив разрешает или считает модой галереи.

Практический вывод: число провалов инструмента не равно числу находок в проекте. На типичной сборке из 15 строк вывода настоящими находками оказываются 3–4; ещё 3 — дефекты самой сборки, остальное — вкус пакета, неприменимые проверки и ложные срабатывания.

## Проверка ложных срабатываний — часть работы

| Симптом | Что делать |
|---|---|
| `off-centre` при разнице полей меньше 40 px | перепроверить по координатам HTML: у проверки бывают ложные из-за скроллбара и разных типов узлов |
| `first-action` уровня WARN | посмотреть глазами: WARN означает «посмотри», а не «сломано» |
| `hero-void` уровня WARN | посчитать долю пустоты вручную; порог 40% из 10.17 |
| находки на 768 и 390, а адаптива в сборке нет | отбросить целиком, а не по одной, если страница рисуется на одну ширину |

## Приёмы, без которых замеры врут

- Закрыть cookie-баннер перед замерами.
- Доскроллить страницу, чтобы сработали reveal-анимации.
- Считать фактическое число строк через `Range.getClientRects()`, а не делением ширины на кегль.
- Цвет фона под текстом подтверждать сэмплом пикселей из PNG: `getComputedStyle` показывает фон предка.
- Длинную страницу резать на куски по 1600 px.
