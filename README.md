# Design Skill

Пакет правил веб-дизайна: 217 пронумерованных правил, измерительные скрипты и рабочий эталон. Подключается к Claude Code, Codex и Cursor и превращает «сделай красиво» в проверяемый процесс.

Два режима:

- **Разбор готового сайта по ссылке.** Скилл снимает страницу на компьютере и на телефоне, находит ошибки замерами, ставит на скриншоте красные кружки с цифрами и пишет отчёт простым русским языком: кружок 1 — сноска 1 «где, что не так, почему мешает, как исправить».
- **Разработка.** Каждое правило переведено в действие («как делать») и в замер («как проверить, порог такой-то»).

## Разбор сайта в Claude Code

После установки (ниже) напиши в Claude Code:

```
Проанализируй сайт https://example.com по design-skill
```

Claude Code сам прогонит замер, проверит находки на скриншотах, расставит кружки и соберёт отчёт. В рабочей папке появится `review-<домен>/`:

| Файл | Что это |
|---|---|
| `report.md` | отчёт: коротко о главном, что сделано хорошо, три первых исправления, снимки с кружками и сноски под ними, техническое приложение с номерами правил |
| `annotated-desktop.png`, `annotated-mobile.png` | вся страница целиком на 1440 и 390 px с кружками |
| `annotated-desktop-1.png`, `-2.png`… | та же страница, нарезанная на части — их и вставляет отчёт |
| `findings.json` | находки в машинном виде: номер, текст, селектор, рамка, правило |
| `shots/` | исходные снимки и замеры `measure.json` |

Пример сноски из отчёта:

> **4. Белый текст на горчичном фоне плохо читается** · блок «О нас» · _важно_
>
> Белый текст (#FFFFFF) на горчичном фоне (#D19E56): контраст 2,4 к 1. Так набраны «Варим кофе с 1838 года», «О нас», «Десерты» и ещё 3. Текст сливается с фоном: на солнце, на недорогом экране и людям со слабым зрением его не прочитать.
>
> Как исправить: нужен контраст не меньше 4,5 к 1 для обычного текста и 3 к 1 для крупных заголовков: набрать текст тёмным #333333 (с этим фоном это 5,3 к 1) или затемнить фон до #986A29.

Номера правил в основном тексте не появляются — только в свёрнутом приложении в конце. Шаблон отчёта — `references/report-template.md`.

Что нужно на компьютере: Node 22+, Chrome или Chromium и `npm install puppeteer-core` в папке скилла (см. «Зависимости»).

## Из чего собрано

| Источник | Что взято |
|---|---|
| Лекции по дизайну клуба web-steps.ru (цвет, шрифт, текст, композиция, UI) | разделы 1–9, 164 правила — главный слой |
| Исследование 247 сайтов-победителей One Page Love и Awwwards + второй замер 100 Sites of the Day | раздел 10, 43 правила с числами |
| Шкала оценки | раздел 11, 10 правил: веса критериев и формулировки балла |
| `taste`-инспектор и пакет `wireframe-agent-skill` | отдельные числа: шкала отступов, тач-зоны, брейкпоинты |
| Наши прототипные правила | `prototype-mode.md`: что остаётся в бесцветном прототипе |

Приоритет жёсткий: **разделы 1–9 главнее раздела 10**. Если исследование говорит «H1 — 72 px», а лекция даёт другую логику, действует лекция; число из раздела 10 — ориентир, а не замена решению. Числа, которых нет в источниках, в пакет не добавлены: где порога нет, правило сформулировано качественно.

Итого 217 правил: 1.1–1.17, 2.1–2.16, 3.1–3.23, 4.1–4.19, 5.1–5.16, 6.1–6.11, 7.1–7.14, 8.1–8.30, 9.1–9.18, 10.1–10.43, 11.1–11.10. Номера не переименовываются: на них ссылаются находки, линтер и чек-лист.

## Установка

### Claude Code

```bash
mkdir -p ~/.claude/skills
cp -r design-skill ~/.claude/skills/design-skill
```

Скилл подхватится по `name` из frontmatter. Проверка — спросить Claude Code, какие скиллы доступны, или начать задачу словами «сверстай лендинг»: `description` в `SKILL.md` написан под автоподбор.

Если нужен один проект, а не все, положи папку в `.claude/skills/` внутри репозитория.

### Cursor

Два рабочих способа.

**Правилом проекта** — короткая обёртка, которая ссылается на пакет:

```bash
mkdir -p .cursor/rules
```

`.cursor/rules/design-skill.mdc`:

```markdown
---
description: Правила веб-дизайна при вёрстке любого сайта или лендинга
globs: ["**/*.html", "**/*.css", "**/*.tsx", "**/*.jsx"]
alwaysApply: false
---

Перед вёрсткой прочитай design-skill/SKILL.md и работай по его шагам.
Файлы references/ читай выборочно по таблице роутера в SKILL.md.
Числа бери только оттуда; порогов не выдумывай.
```

**Папкой скилла** — если в проекте используется формат skills, скопируй `design-skill/` в `.cursor/skills/design-skill/` и оставь `SKILL.md` с тем же frontmatter.

### Codex

Codex читает `AGENTS.md` из корня проекта. Положи пакет рядом и добавь ссылку:

```markdown
## Дизайн и вёрстка

Перед любой работой с HTML/CSS/UI прочитай `design-skill/SKILL.md` и следуй
порядку шагов. Справочники — в `design-skill/references/` (роутер в SKILL.md).
Готовые переменные — `design-skill/references/tokens.css`.
Проверка перед сдачей: `python3 design-skill/scripts/lint-design.py index.html`
и чек-лист `references/checklist.md`.
```

Путь можно не копировать, а подключить симлинком, если пакет лежит в общем каталоге:

```bash
ln -s ~/skills/design-skill ./design-skill
```

## Скрипты

### lint-design.py — быстрая проверка без браузера

```bash
python3 scripts/lint-design.py index.html
python3 scripts/lint-design.py index.html --greyscale   # режим прототипа: ловит цветную заливку и тени
python3 scripts/lint-design.py index.html --json        # машинный вывод
python3 scripts/lint-design.py index.html --css extra.css  # плюс внешний CSS
```

Что проверяет: кегли вне шкалы (10.6, 10.1–10.5), отступы не кратные 8 (10.18), радиусы вне набора 0/12/16/24/капсула (8.8), больше пяти разных кеглей (10.6), отсутствие h1 и больше одного h1 (3.1), перескок уровня заголовка (3.1), цветную заливку и тени при `--greyscale` (1.14), контраст пар текст/фон по hex (10.22: 4,5:1 и 3:1 для крупного). Работает и с инлайн-стилями, и с `<style>`, понимает `var(--x, fallback)` до трёх уровней вложенности — поэтому копия `tokens.css` не даёт ложных срабатываний.

Коды выхода: `0` — чисто, `1` — есть кандидаты, `2` — файл не найден или не разобран.

### audit.js → check.py → annotate.js → report.py — разбор живого сайта

```bash
npm install puppeteer-core          # один раз в папке скилла
node scripts/audit.js https://example.com review/shots/             # пишет review/shots/measure.json и снимки
python3 scripts/check.py review/shots/ --json review/findings.json  # находки + файл для кружков
# (по желанию) поправить findings.json руками, затем:
python3 scripts/check.py --renumber review/findings.json
node scripts/annotate.js https://example.com review/findings.json review/   # annotated-*.png + annotated.json
python3 scripts/report.py review/findings.json review/annotated.json review/report.md
node scripts/shots.js https://example.com shots/ 0,1200,2400        # отдельные участки на 1440
```

`audit.js` открывает страницу в Chrome в двух видах — 1440×900 и 390×844 (на телефоне — с мобильным user-agent), закрывает cookie-баннер и всплывающие окна, прокручивает страницу до конца, чтобы догрузились картинки и анимации, и собирает метрики: тексты с цветом и фоном под ними (фон-фотографию определяет по пикселям), кнопки, кегли, отступы, радиусы, палитру по площади, тени, секции, переполнение по ширине. У каждого элемента сохраняются CSS-селектор и рамка в координатах страницы.

`check.py` переводит метрики в находки человеческим языком — где, что не так, почему мешает, как исправить — и хранит номер правила отдельно: контраст (в том числе на фото), мелкий текст, высота и площадь нажатия кнопок, «Подробнее» на кнопке, H1, заголовки в три строки, длина строки и интерлиньяж, выключка, капс, горизонтальная прокрутка на телефоне, текст у края экрана, число цветов, шрифтов, кеглей, тени и радиусы. Без `--json` печатает список в консоль.

`annotate.js` снимает страницу целиком и рисует красную рамку вокруг каждого элемента и красный кружок с белой цифрой рядом, стараясь не закрывать текст. Длинная страница режется на части (`--part 1800` — высота части в px). Если селектор не нашёлся, кружок ставится по сохранённой рамке; не встал вовсе — об этом пишет консоль и `annotated.json`.

`report.py` собирает `report.md`: картинки частей и под каждой — сноски с номерами её кружков. Раздел «Коротко» — черновик, агент переписывает его своими словами.

Коды выхода `audit.js`: `0` — замер записан, `2` — не указан адрес, `3` — страница не открылась. Если страница не отдала содержимое, скрипт не пишет пустой `measure.json`, чтобы `check.py` потом не принимал его за сайт без заголовков.

### Зависимости

| Инструмент | Требуется |
|---|---|
| `lint-design.py`, `check.py`, `report.py` | Python 3.8+, никаких пакетов |
| `audit.js`, `annotate.js`, `shots.js` | Node 22+, установленный Chrome или Chromium, `puppeteer-core` |

Если Chrome лежит не в стандартном месте, путь задаётся переменной `CHROME_PATH`:

```bash
CHROME_PATH=/usr/bin/google-chrome node scripts/audit.js https://example.com shots/
```

## Как этим пользоваться

1. Открой `SKILL.md` — это роутер. Он задаёт 11 шагов от брифа до балла.
2. На каждом шаге читай только тот файл из `references/`, который указан в таблице роутера. Справочники длинные намеренно: их читают выборочно, а не целиком.
3. Значения не изобретай — бери из `tokens.css` и `thresholds.md`.
4. Перед сдачей прогони линтер, пройди `checklist.md` сверху вниз и посмотри на скриншот по `screen-check.md`.
5. Отчитайся в формате из конца `SKILL.md`: решения, замеры, находки с номерами, балл по весам 11.1.

Для разбора чужого сайта достаточно фразы «Проанализируй сайт https://… по design-skill» — порядок шагов описан в `SKILL.md`, раздел «Разбор существующего сайта».

`examples/landing.html` — эталон того, как выглядит результат, проходящий проверку: один h1, пять кеглей, отступы по шкале, кнопки 56 px, четыре состояния, фокус, `prefers-reduced-motion`, alt у картинок, семантические теги, ноль замечаний линтера.

## Границы

- Скилл описывает то, что есть в источниках. Цветовых схем, пропорции 60/30/10, правил дальтонизма, OKLCH и тёмной темы в источниках нет — по этим темам пакет молчит намеренно, чтобы не выдумывать пороги.
- Числа раздела 10 — из галереи, а галерея это мода. Медианный сайт самого исследования нарушает четыре своих же правила. Число — инструмент, решение остаётся за дизайнером.
- Разбор живого сайта не снимет страницу, закрытую от роботов, капчей, защитой Cloudflare или входом в кабинет. Всплывающие окна закрываются эвристикой — редкий попап может остаться на снимке. Слайдеры и анимации могут показать на снимке не тот кадр, что был при замере. Контраст текста на фотографии — приближённый (медианный цвет под текстом); на очень пёстром фото скрипт его не оценивает, это делает агент глазами. Находки скриптов — кандидаты: агент подтверждает их по снимку.
- Линтер статический: он не знает про каскад, наследование и вычисленные стили. Его вывод — кандидаты, а не приговор; окончательно подтверждает скриншот.
